# 流程引擎接口文档

## 通用说明

### 基础路径
```
http://{host}:{port}
```

### 认证方式
所有接口需在请求头携带 Token：
```
Authorization: Bearer {token}
```

### 统一响应格式
```json
{
  "code": 200,
  "message": "操作成功",
  "data": {}
}
```

### 权限标识格式
Warm-Flow 使用权限标识控制任务可见性和操作权限：
- 角色格式：`role:{roleCode}`（如 `role:super_admin`）
- 用户格式：`user:{userId}`（如 `user:1`）

## 1. 流程定义管理 `/flowDef`

### 1.1 分页列表
```
GET /flowDef/list
```
**权限**: `system:flow:def:list`

| 参数 | 类型 | 必填 | 说明 |
|------|------|------|------|
| current | int | 否 | 当前页，默认 1 |
| size | int | 否 | 每页条数，默认 10 |
| flowCode | String | 否 | 流程编码（模糊匹配） |
| flowName | String | 否 | 流程名称（模糊匹配） |
| isPublish | Integer | 否 | 发布状态（0-未发布 1-已发布） |

**响应 data**: `List<FlowDefVo>`
```json
[{
  "id": "196379784727543808",
  "flowCode": "leave-apply",
  "flowName": "请假申请",
  "version": "1",
  "isPublish": 1,
  "isActive": 1,
  "listenerType": "com.mikuyun.admin.service.flow.listennr.DefStartListener",
  "description": "员工请假审批流程",
  "createBy": "1",
  "createByName": "管理员",
  "createTime": "2026-06-18 10:30:00",
  "updateTime": "2026-06-18 14:00:00"
}]
```

### 1.2 流程详情（含节点）

```
GET /flowDef/detail/{id}
```

**权限**: `system:flow:def:list`

| 参数 | 类型 | 必填 | 说明 |
|------|------|------|------|
| id | Long | 是 | 流程定义 ID（路径参数） |

**响应 data**: `FlowDefVo`
```json
{

  "flowCode": "leave-apply",
  "flowName": "请假申请",
  "isPublish": 1,

      "permissionFlag": null
    },
    {
      "id": "196379784727543810",
      "definitionId": 196379784727543808,
      "nodeCode": "2",
      "nodeName": "部门经理审批",
      "nodeType": 1,
      "permissionFlag": "role:dept_manager"
```

### 1.3 获取流程设计数据（JSON）
```
GET /flowDef/design/{id}
```
**权限**: `system:flow:def:list`

返回流程设计的完整 JSON 数据，供流程设计器加载。

### 1.4 发布流程
```
POST /flowDef/publish?id={id}
```
**权限**: `system:flow:def:edit`

### 1.5 取消发布
```
POST /flowDef/unPublish?id={id}
```
**权限**: `system:flow:def:edit`

### 1.6 激活流程
```
POST /flowDef/active?id={id}
```
**权限**: `system:flow:def:edit`

### 1.7 挂起流程
```
POST /flowDef/unActive?id={id}
```
**权限**: `system:flow:def:edit`

### 1.8 删除流程
```
POST /flowDef/del
Content-Type: application/json

{
  "idList": [123, 456]
}
```
**权限**: `system:flow:def:delete`

### 1.9 复制流程
```
POST /flowDef/copy?id={id}
```
**权限**: `system:flow:def:add`

## 2. 流程实例管理 `/flowIns`

### 2.1 分页列表
```
GET /flowIns/list
```
**权限**: `system:flow:ins:list`

| 参数 | 类型 | 必填 | 说明 |
|------|------|------|------|
| current | int | 否 | 当前页 |
| size | int | 否 | 每页条数 |
| definitionId | Long | 否 | 流程定义 ID |
| businessId | String | 否 | 业务 ID |
| flowStatus | String | 否 | 流程状态（toDo/pass/reject/complete/termination） |
| createBy | String | 否 | 发起人 ID |

**响应 data**: `List<FlowInsVo>`
```json
[{
  "id": "196379784727543808",
  "definitionId": "196379784727543808",
  "flowCode": "leave-apply",
  "flowName": "请假申请",
  "businessId": "1001",
  "nodeType": 1,
  "nodeCode": "2",
  "nodeName": "部门经理审批",
  "flowStatus": "toDo",
  "createBy": "1",
  "createByName": "张三",
  "createTime": "2026-06-18 10:30:00",
  "updateTime": "2026-06-18 10:30:00"
}]
```

### 2.2 实例详情
```
GET /flowIns/detail/{id}
```
**权限**: `system:flow:ins:list`

### 2.3 启动流程
```
POST /flowIns/start
Content-Type: application/json

{
  "flowCode": "leave-apply",
  "businessId": "1001",
  "message": "申请年假5天",
  "variable": {
    "days": 5,
    "reason": "年假"
  },
  "permissionFlag": ["role:hr_manager"]
}
```
**权限**: `system:flow:ins:start`

| 参数 | 类型 | 必填 | 说明 |
|------|------|------|------|
| flowCode | String | **是** | 流程编码 |
| businessId | String | **是** | 业务数据 ID |
| message | String | 否 | 发起说明/备注 |
| variable | Map | 否 | 流程变量（JSON 对象） |
| permissionFlag | List | 否 | 额外权限标识（当前用户角色已自动注入） |

> **改造说明**: 当前用户 ID 和角色权限标识会自动注入，无需手动传入 handler。

### 2.4 激活/挂起/删除

| 接口 | 方法 | 权限 |
|------|------|------|
| `/flowIns/active/{id}` | POST | `system:flow:ins:edit` |
| `/flowIns/unActive/{id}` | POST | `system:flow:ins:edit` |
| `/flowIns/del` | POST | `system:flow:ins:delete` |

## 3. 流程任务管理 `/flowTask`

### 3.1 我的待办
```
GET /flowTask/myTodo
```
**权限**: `system:flow:task:list`

| 参数 | 类型 | 必填 | 说明 |
|------|------|------|------|
| current | int | 否 | 当前页 |
| size | int | 否 | 每页条数 |
| definitionId | Long | 否 | 流程定义 ID |
| instanceId | Long | 否 | 流程实例 ID |
| flowStatus | String | 否 | 任务状态 |

> **改造说明**: 自动过滤为当前用户的待办任务，无需手动传入用户 ID。

**响应 data**: `List<FlowTaskVo>`
```json

  "instanceId": "196379784727543810",
```

### 3.3 任务详情
```
GET /flowTask/detail/{id}
```
**权限**: `system:flow:task:list`

### 3.4 审批历史
```
GET /flowTask/hisList/{instanceId}
```
**权限**: `system:flow:task:list`

按创建时间正序返回完整审批链路。

### 3.5 审批通过
```
POST /flowTask/pass
Content-Type: application/json

{
  "taskId": 196379784727543811,
  "message": "同意",
  "variable": {
    "approvedBy": "李四"
  }
}
```
**权限**: `system:flow:task:approve`

| 参数 | 类型 | 必填 | 说明 |
|------|------|------|------|
| taskId | Long | * | 任务 ID（与 instanceId 二选一） |
| instanceId | Long | * | 实例 ID（与 taskId 二选一） |
| message | String | 否 | 审批意见 |
| variable | Map | 否 | 流程变量 |
| nodeCode | String | 否 | 目标节点编码（自由跳转） |

> **改造说明**: 当前操作用户 ID 自动注入，无需手动传入 handler。

### 3.6 审批驳回
```
POST /flowTask/reject
```
参数同 3.5。**权限**: `system:flow:task:approve`

### 3.7 转办
```
POST /flowTask/transfer

{
  "taskId": 196379784727543811,
  "addHandlers": ["3", "4"],
  "message": "转交王五处理"
}
```
**权限**: `system:flow:task:approve`

| 参数 | 类型 | 必填 | 说明 |
|------|------|------|------|
| taskId | Long | **是** | 任务 ID |
| addHandlers | List\<String\> | **是** | 转办目标用户 ID 列表 |
| message | String | 否 | 转办说明 |

### 3.8 委派
```
POST /flowTask/depute
```
参数格式同转办。**权限**: `system:flow:task:approve`

### 3.9 加签
```
POST /flowTask/addSignature
```
参数格式同转办。**权限**: `system:flow:task:approve`

### 3.10 减签
```
POST /flowTask/reductionSignature

{
  "taskId": 196379784727543811,
  "reductionHandlers": ["3"],
  "message": "移除审批人"
}
```
**权限**: `system:flow:task:approve`

| 参数 | 类型 | 必填 | 说明 |
|------|------|------|------|
| taskId | Long | **是** | 任务 ID |
| reductionHandlers | List\<String\> | **是** | 要移除的用户 ID 列表 |
| message | String | 否 | 说明 |

### 3.11 终止流程
```
POST /flowTask/termination
POST /flowTask/termination?instanceId=xxx
```
**权限**: `system:flow:task:approve`

支持通过 taskId 或 instanceId 终止。

### 3.12 撤销流程
```
POST /flowTask/revoke

{
  "instanceId": 196379784727543810,
  "message": "申请信息有误，撤销重提"
}
```
**权限**: `system:flow:task:approve`

| 参数 | 类型 | 必填 | 说明 |
|------|------|------|------|
| instanceId | Long | **是** | 流程实例 ID |
| message | String | 否 | 撤销说明 |

### 4.1 保存流程设计
```
POST /warm-flow/saveJson

{
  "id": 123,
  "flowCode": "leave-apply",

  "description": "员工请假审批流程",
```

### 4.2 查询流程定义
```
GET /warm-flow/queryDef?id={definitionId}
```

### 4.3 查询流程图
```
GET /warm-flow/queryFlowChart?id={definitionId}
```

### 4.4 获取处理人类型
```
GET /warm-flow/handlerType

响应: ["user", "role", "dept"]
```

## 5. 错误码参考

| 错误码 | 说明 |
|--------|------|
| 200 | 操作成功 |
| 401 | 未授权（Token 无效或缺失） |
| 403 | 无权限（缺少对应权限标识） |
| 10401 | Token 无效 |
| 10402 | Token 已过期 |

### Warm-Flow 内部错误
流程引擎内部会抛出 `IllegalArgumentException` 等异常，由全局异常处理器统一返回 `R.error()`。

常见错误：
- `"任务不存在: xxx"` — taskId 无效
- `"流程编码不能为空"` — 启动流程时 flowCode 为空
- `"业务ID不能为空"` — 启动流程时 businessId 为空

## 6. 完整调用示例

### 6.1 发起审批流程
```bash
# 1. 登录获取 Token
curl -X POST http://localhost:8091/auth/login \
  -H "Content-Type: application/json" \
  -d '{"username":"admin","password":"123456"}'

# 响应: {"code":200,"data":{"accessToken":"xxx-xxx-xxx"}}

# 2. 启动流程
curl -X POST http://localhost:8091/flowIns/start \
  -H "Authorization: Bearer xxx-xxx-xxx" \
  -H "Content-Type: application/json" \
  -d '{
    "flowCode": "leave-apply",
    "businessId": "1001",
    "message": "申请年假5天",
    "variable": {"days": 5, "reason": "年假"}
  }'

# 3. 查看我的待办
curl http://localhost:8091/flowTask/myTodo \
  -H "Authorization: Bearer xxx-xxx-xxx"

# 4. 审批通过
curl -X POST http://localhost:8091/flowTask/pass \
  -H "Authorization: Bearer xxx-xxx-xxx" \
  -H "Content-Type: application/json" \
  -d '{"taskId": 196379784727543811, "message": "同意"}'

# 5. 查看审批历史
curl http://localhost:8091/flowTask/hisList/196379784727543810 \
  -H "Authorization: Bearer xxx-xxx-xxx"
```
