# 流程引擎用户体系集成改造说明

## 1. 改造概述

### 1.1 改造背景

项目已集成 Warm-Flow 1.8.7 流程引擎，但未与后台用户体系打通，存在以下问题：
- 流程操作未关联当前登录用户（`handler` 未设置）
- 待办/已办任务未按用户隔离
- 权限标识（`permissionFlag`）需手动传入
- 流程设计器 API（`/warm-flow/*`）无鉴权
- 返回数据中只有用户 ID，缺少用户姓名

### 1.2 改造目标

| 目标 | 说明 |
|------|------|
| 自动用户关联 | 操作时自动注入当前登录用户 ID、姓名、角色 |
| 任务隔离 | 待办/已办查询只返回当前用户相关任务 |
| 权限自动推导 | `permissionFlag` 自动从用户角色生成 |
| API 安全 | 流程设计器 API 加入 Token 鉴权 |
| 用户姓名展示 | VO 返回中包含用户姓名 |

## 2. 架构设计

### 2.1 用户体系桥接

```
┌─────────────────────────────────────────────────┐
│                Sa-Token (认证层)                  │
│  StpUtil.getLoginId() → 当前用户 ID (Integer)    │
│  StpUtil.getRoleList() → 当前用户角色列表          │
└───────────────────┬─────────────────────────────┘
                    │
┌───────────────────▼─────────────────────────────┐
│           FlowUserContext (桥接层)                │
│  getCurrentUserId()     → String 用户ID           │
│  getCurrentUserName()   → String 用户姓名          │
│  getCurrentRoleFlags()  → ["role:xxx", ...]       │
│  buildFlowParams()      → FlowParams (预填充)      │
│  getUserNameMap(ids)    → Map<ID, Name>           │
└───────────────────┬─────────────────────────────┘
                    │
┌───────────────────▼─────────────────────────────┐
│           Warm-Flow (流程引擎)                     │
│  FlowParams.handler()        ← 自动注入用户ID      │
│  FlowParams.permissionFlag() ← 自动注入角色标识     │
│  TaskService / InsService    ← 引擎核心操作         │
└─────────────────────────────────────────────────┘
```

### 2.2 安全架构

```
浏览器请求 /warm-flow/*
    │
    ▼
┌──────────────────────────┐
│ WarmFlowSecurityFilter   │  ← 新增：校验 Bearer Token
│ (拦截 /warm-flow/*)       │
└──────────┬───────────────┘
           │ Token 有效
           ▼
┌──────────────────────────┐
│ WarmFlowController       │  ← Warm-Flow 内置
│ (流程设计器 REST API)     │
└──────────────────────────┘
```

`/warm-flow-ui/**` 静态资源不经过 Filter，保持可访问。

## 3. 新增文件说明

### 3.1 FlowUserContext (核心桥接)

**路径**: `service/flow/FlowUserContext.java`

静态工具类，桥接 Sa-Token 用户体系与 Warm-Flow 流程引擎。

```java
// 获取当前用户上下文
String userId = FlowUserContext.getCurrentUserId();      // "1"
String userName = FlowUserContext.getCurrentUserName();  // "张三"
List<String> flags = FlowUserContext.getCurrentRoleFlags(); // ["role:admin"]

// 构建预填充的 FlowParams（自动注入 handler + permissionFlag）
FlowParams params = FlowUserContext.buildFlowParams("leave-apply");

// 批量 ID → 姓名映射
Map<String, String> nameMap = FlowUserContext.getUserNameMap(List.of("1", "2"));
```

### 3.2 FlowHandlerSelectServiceImpl (设计器用户选择)

**路径**: `service/flow/FlowHandlerSelectServiceImpl.java`

实现 Warm-Flow 的 `HandlerSelectService` 接口，流程设计器在处理人节点配置时调用，查询系统用户列表。

支持的查询类型：
- `user` — 按用户名/姓名搜索 `mk_sys_user` 表
- `role` — 按角色搜索（预留）
- `dept` — 按部门搜索（预留）

### 3.3 WarmFlowSecurityFilter (安全过滤)

**路径**: `config/WarmFlowSecurityFilter.java`

Spring Filter，对 `/warm-flow/*` API 调用进行 Token 鉴权：
1. 从 `Authorization: Bearer xxx` 请求头提取 Token
2. 也支持 URL 参数 `?token=xxx`（流程设计器 iframe 嵌入场景）
3. 调用 `StpUtil.getLoginIdByToken()` 验证
4. 失败返回 401 JSON

### 3.4 FilterConfig (过滤器注册)

**路径**: `config/FilterConfig.java`

通过 `FilterRegistrationBean` 将 `WarmFlowSecurityFilter` 注册到 `/warm-flow/*` 路径。

## 4. 修改文件说明

### 4.1 FlowInsServiceImpl — 启动流程自动注入用户

**变更**: `start()` 方法使用 `FlowUserContext.buildFlowParams()` 自动注入 `handler` 和 `permissionFlag`。

```java
// 改造前
FlowParams flowParams = FlowParams.build()
    .flowCode(dto.getFlowCode())
    .variable(dto.getVariable());

// 改造后
FlowParams flowParams = FlowUserContext.buildFlowParams(dto.getFlowCode())
    .variable(dto.getVariable())
    .message(dto.getMessage());
// handler → 当前用户 ID
// permissionFlag → 当前用户角色标识
```

### 4.2 FlowTaskServiceImpl — 待办隔离 + 操作用户注入

**变更 1**: `myTodoList()` / `myDoneList()` 查询条件中加入 `setCreateBy(currentUserId)`
```java
Task query = FlowEngine.newTask();
query.setCreateBy(FlowUserContext.getCurrentUserId()); // 只查我的待办
```

**变更 2**: `buildFlowParams()` 自动注入当前用户
```java
private FlowParams buildFlowParams(FlowActionDto dto) {
    FlowParams flowParams = FlowUserContext.buildFlowParams() // handler + permissionFlag 已注入
        .message(dto.getMessage())
        .variable(dto.getVariable());
    // ...
}
```

### 4.3 VO 增强 — 添加用户姓名字段

所有流程相关 VO 新增 `createByName` 字段：

| VO | 新增字段 | 说明 |
|----|---------|------|
| `FlowDefVo` | `createByName` | 流程定义创建人姓名 |
| `FlowInsVo` | `createByName` | 流程发起人姓名 |
| `FlowTaskVo` | `createByName` | 任务创建人姓名 |
| `FlowHisTaskVo` | `createByName` | 历史任务创建人姓名 |

Service 层在返回列表前调用 `FlowUserContext.getUserNameMap()` 批量填充。

### 4.4 DefStartListener — 注册为 Spring Bean

添加 `@Component` 注解，Warm-Flow 自动发现并注册该监听器。

## 5. 配置说明

### 5.1 无需额外配置

改造不引入新的配置项，利用现有：
- Sa-Token 配置（token-name、timeout 等）
- Warm-Flow 自动配置（数据库表、ORM 映射）
- Spring 依赖注入

### 5.2 数据库

无需变更。Warm-Flow 的 `createBy`（String 类型）存储 `mk_sys_user.id` 的字符串形式，天然兼容。

### 5.3 权限标识格式

Warm-Flow 的 `permissionFlag` 格式为 `role:xxx` 或 `user:xxx`：
- 角色标识：`["role:super_admin", "role:dept_manager"]`
- 用户标识：`["user:1", "user:2"]`

改造后自动生成当前用户的角色标识列表，由引擎内部用于匹配任务的处理人权限。

## 6. 流程设计器使用

### 6.1 访问设计器

```
http://localhost:8091/warm-flow-ui/index.html
```

设计器页面本身无需认证（静态资源），但保存/加载等 API 调用需要 Token。

### 6.2 Token 传递

流程设计器通过 `token` URL 参数传递认证令牌：

```
http://localhost:8091/warm-flow-ui/index.html?token=xxx
```

`WarmFlowSecurityFilter` 支持从 URL 参数提取 Token。

### 6.3 处理人配置

在流程设计器的审批节点中，配置处理人时：
- 选择 "用户" — 通过 `FlowHandlerSelectServiceImpl` 查询系统用户
- 选择 "角色" — 预留，可扩展为查询角色表
- 权限标识格式：`role:roleCode` 或 `user:userId`

## 7. 扩展指南

### 7.1 添加角色/部门处理人选择

在 `FlowHandlerSelectServiceImpl` 中实现 `role` 和 `dept` 分支：

```java
case "role" -> {
    SysRoleService roleService = SpringContextUtils.getBean(SysRoleService.class);
    List<SysRole> roles = roleService.list();
    return roles.stream()
        .map(role -> new HandlerAuth()
            .setStorageId(String.valueOf(role.getId()))
            .setHandlerCode(role.getRoleCode())
            .setHandlerName(role.getRoleName()))
        .collect(Collectors.toList());
}
```

### 7.2 添加更多流程监听器

参考 `DefStartListener`，实现 `Listener` 接口并添加 `@Component` 注解：

```java
@Component
public class DefFinishListener implements Listener {
    @Override
    public void notify(ListenerVariable variable) {
        Instance instance = variable.getInstance();
        log.info("流程 {} 完成", instance.getFlowName());
    }
}
```

### 7.3 自定义权限标识策略

修改 `FlowUserContext.getCurrentPermissionFlags()` 方法，添加部门标识等：
```java
public static List<String> getCurrentPermissionFlags() {
    List<String> flags = new ArrayList<>(getCurrentRoleFlags());
    flags.add("user:" + getCurrentUserId());
    flags.add("dept:" + getCurrentUserDeptId()); // 自定义
    return flags;
}
```

## 8. 注意事项

1. **Warm-Flow 版本**: 当前 1.8.7，升级时需验证 `HandlerSelectService` 接口兼容性
2. **handler 查询**: 待办查询使用 `createBy` 字段过滤，在转办/会签等多处理人场景下可能漏查。如需精确查询，可扩展为 `flow_user` 关联查询
3. **流程设计器前端**: warm-flow-ui 为内置 SPA，无法修改源码。如需定制 UI，需自行开发前端页面
4. **权限标识**: 节点配置的 `permissionFlag` 需与 `FlowUserContext` 生成的格式一致（如 `role:dept_manager`）
