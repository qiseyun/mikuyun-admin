# 流程引擎使用指南

## 1. 前置准备

### 1.1 环境要求

| 组件 | 版本要求 | 说明 |
|------|---------|------|
| JDK | 21+ | 项目编译运行基础 |
| MySQL | 8.0+ | 业务数据 + 流程数据存储 |
| Redis | 6.0+ | Sa-Token 认证缓存 |
| Maven | 3.8+ | 项目构建 |

可选组件（按需启用）：
- Nacos — 配置中心（`local`/`prod` profile）
- RocketMQ — 消息队列
- XXL-JOB — 定时任务

### 1.2 数据库初始化

**步骤 1: 建库建表**

执行项目自带的初始化 SQL（`01_docs/01_database_mysql8/`）：
```sql
-- 建库
CREATE SCHEMA mikuyun COLLATE utf8mb4_0900_ai_ci;
USE mikuyun;

-- 然后依次执行：
-- 01_建库建表.sql    (业务表: mk_sys_user, mk_sys_role, mk_sys_user_role, mk_sys_permissions 等)
-- 02_初始化数据.sql  (初始管理员账号、角色、权限等)
```

**步骤 2: 流程引擎表（自动创建）**

Warm-Flow 流程引擎的表由 MyBatis-Plus DDL 自动创建，**首次启动应用时自动生成**，无需手动执行 SQL。

自动创建的表包括：

| 表名 | 说明 |
|------|------|
| `flow_definition` | 流程定义 |
| `flow_instance` | 流程实例 |
| `flow_task` | 待办任务 |
| `flow_his_task` | 历史任务（已办记录） |
| `flow_node` | 流程节点 |
| `flow_user` | 用户-任务关联 |
| `flow_skip` | 流转跳转记录 |

> **注意**: 确保数据库用户有 CREATE TABLE 权限。若生产环境不允许自动 DDL，可先在内网启动一次导出 DDL，再在生产库执行。

**步骤 3: 验证表创建**

启动应用后，连接数据库执行：
```sql
USE mikuyun;
SHOW TABLES LIKE 'flow_%';
```
应看到上述 7 张表。

### 1.3 认证体系确认

流程引擎依赖 Sa-Token 用户体系，需确保：

1. `mk_sys_user` 表有用户数据（初始化 SQL 会创建管理员 `admin`）
2. `mk_sys_role` 表有角色数据（`super_admin` 等）
3. `mk_sys_user_role` 表有关联数据
4. `mk_sys_permissions` 表有流程相关权限：

```sql
-- 流程引擎所需权限（初始化 SQL 已包含）
-- 流程定义
INSERT INTO mk_sys_permissions (name, permission, type, parent_id) VALUES
('流程定义列表', 'system:flow:def:list', 2, <menu_id>),
('流程定义新增', 'system:flow:def:add', 2, <menu_id>),
('流程定义编辑', 'system:flow:def:edit', 2, <menu_id>),
('流程定义删除', 'system:flow:def:delete', 2, <menu_id>),

-- 流程实例
('流程实例列表', 'system:flow:ins:list', 2, <menu_id>),
('发起流程', 'system:flow:ins:start', 2, <menu_id>),
('流程实例编辑', 'system:flow:ins:edit', 2, <menu_id>),
('流程实例删除', 'system:flow:ins:delete', 2, <menu_id>),

-- 流程任务
('任务列表', 'system:flow:task:list', 2, <menu_id>),
('任务审批', 'system:flow:task:approve', 2, <menu_id>);
```

### 1.4 启动应用

```bash
# 确保 MySQL 和 Redis 已启动

# 开发模式（使用 Nacos local 配置）
mvn spring-boot:run

# 或打包运行
mvn clean package -DskipTests
java -jar target/mikuyun-admin-1.0.0.jar --spring.profiles.active=local
```

启动日志中应出现 Warm-Flow banner，表示流程引擎加载成功。

## 2. 快速入门 — 5 分钟跑通一条审批流

### 2.1 登录获取 Token

```bash
curl -X POST http://localhost:8091/auth/login \
  -H "Content-Type: application/json" \
  -d '{"username":"admin","password":"admin123"}'

# 响应
{
  "code": 200,
  "data": {
    "accessToken": "xxxxxxxx-xxxx-xxxx-xxxx-xxxxxxxxxxxx",
    "expiresTime": 1735689600
  }
}
```

后续所有请求在 Header 中携带：
```
Authorization: Bearer xxxxxxxx-xxxx-xxxx-xxxx-xxxxxxxxxxxx
```

### 2.2 创建第一个流程定义

#### 方式一：使用内置流程设计器（推荐）

1. 浏览器访问流程设计器：
   ```
   http://localhost:8091/warm-flow-ui/index.html?token=<上一步获取的token>
   ```

2. 在设计器中拖拽设计流程：
   - 从左侧拖入 **开始节点**
   - 拖入 **审批节点**，配置：
     - 节点名称：`部门经理审批`
     - 处理人类型：选择 `用户`
     - 处理人：搜索并选择具体用户
   - 拖入 **结束节点**
   - 用连线连接三个节点

3. 点击 **保存**，填写流程编码和名称：
   - 流程编码：`leave-apply`（唯一标识，后续发起时使用）
   - 流程名称：`请假申请`

4. 设计器自动调用 `/warm-flow/saveJson` 保存，Token 由 URL 参数自动携带。

#### 方式二：直接导入 JSON 流程定义

```bash
curl -X POST http://localhost:8091/warm-flow/saveJson \
  -H "Authorization: Bearer <token>" \
  -H "Content-Type: application/json" \
  -d '{
    "flowCode": "leave-apply",
    "flowName": "请假申请",
    "description": "员工请假审批流程",
    "flowDesignData": "<流程设计JSON>"
  }'
```

### 2.3 发布流程

流程创建后处于"未发布"状态，需要发布后才能启动：

```bash
# 先查询流程定义 ID
curl http://localhost:8091/flowDef/list?flowCode=leave-apply \
  -H "Authorization: Bearer <token>"

# 发布流程（假设 id=196379784727543808）
curl -X POST "http://localhost:8091/flowDef/publish?id=196379784727543808" \
  -H "Authorization: Bearer <token>"
```

> 也可在前端管理页面点击"发布"按钮。

### 2.4 启动流程实例

```bash
curl -X POST http://localhost:8091/flowIns/start \
  -H "Authorization: Bearer <token>" \
  -H "Content-Type: application/json" \
  -d '{
    "flowCode": "leave-apply",
    "businessId": "1001",
    "message": "申请年假5天",
    "variable": {
      "days": 5,
      "reason": "年假",
      "startDate": "2026-07-10",
      "endDate": "2026-07-14"
    }
  }'

# 响应
{
  "code": 200,
  "data": {
    "id": "196379784727543810",
    "flowCode": "leave-apply",
    "flowName": "请假申请",
    "businessId": "1001",
    "flowStatus": "toDo",
    "createBy": "1",
    "createByName": "管理员"
  }
}
```

关键点：
- `flowCode` — 对应流程定义编码
- `businessId` — 关联你的业务数据主键（如请假单 ID）
- `variable` — 流程变量，可在条件分支中使用
- **发起人自动为当前登录用户**，无需手动指定

## 3. 流程设计器详解

### 3.1 访问方式

```
http://localhost:8091/warm-flow-ui/index.html?token=<token>
```

> 必须带 `token` 参数，否则保存等操作会返回 401。

### 3.2 节点类型

| 节点 | 说明 | 配置要点 |
|------|------|---------|
| **开始节点** | 流程入口 | 无需配置 |
| **审批节点** | 需要人工审批 | 设置处理人（用户/角色）、权限标识 |
| **条件节点** | 根据条件分支 | 设置条件表达式（SpEL） |
| **结束节点** | 流程出口 | 无需配置 |

### 3.3 处理人配置

在审批节点中，点击"处理人"配置：

| 处理人类型 | 说明 | storageId/handlerCode 格式 |
|-----------|------|--------------------------|
| **用户** | 指定具体用户 | `用户ID`（如 `1`, `2`, `3`） |
| **角色** | 指定角色下的所有用户 | `role:角色编码`（如 `role:dept_manager`） |

设计器调用 `/warm-flow/handlerResult?handlerType=user&handlerCode=张` 搜索用户。

### 3.4 条件表达式

在条件节点的连线上配置条件，使用 SpEL 表达式：

```java
// 判断流程变量 days > 3
#{variable.get('days') > 3}

// 判断流程变量 reason 包含 "年假"
#{variable.get('reason').contains('年假')}

// 判断审批结果 flag == '1'（通过）
#{flag == '1'}
```

### 3.5 权限标识

在审批节点的"权限标识"中配置，格式为逗号分隔：

```
role:dept_manager,role:super_admin,user:1
```

引擎在创建任务时，会根据权限标识匹配处理人：
- `role:xxx` — 匹配拥有该角色的所有用户
- `user:xxx` — 匹配指定用户

改造后，**当前登录用户的角色标识会自动注入**，无需在代码中手动指定。

## 4. 常见业务场景

### 4.1 请假审批流程

```
[开始] → [部门经理审批] → {条件: days>3?} 
                              ├── 是 → [总经理审批] → [结束]
                              └── 否 → [结束]
```

**步骤**：
1. 设计器中创建上述流程，`flowCode=leave-apply`
2. 部门经理审批节点：处理人类型 `角色`，权限标识 `role:dept_manager`
3. 总经理审批节点：处理人类型 `角色`，权限标识 `role:general_manager`
4. 条件连线：`#{variable.get('days') > 3}`
5. 发布流程

**发起**：
```bash
curl -X POST http://localhost:8091/flowIns/start \
  -H "Authorization: Bearer <token>" \
  -H "Content-Type: application/json" \
  -d '{"flowCode":"leave-apply","businessId":"1001","variable":{"days":5}}'
```

### 4.2 报销审批流程

```
[开始] → [财务审批] → [结束]
```

**步骤**：
1. 设计器中创建流程，`flowCode=expense-approval`
2. 财务审批节点：权限标识 `role:finance`
3. 发布流程

### 4.3 多人会签

在审批节点中配置多个处理人，勾选"会签"模式：
- 所有处理人都审批通过后，流程才流转到下一节点

### 4.4 驳回后重新提交

驳回后，流程回到发起人，发起人可修改业务数据后重新发起（需要业务代码支持）：
```bash
# 驳回
curl -X POST http://localhost:8091/flowTask/reject \
  -H "Authorization: Bearer <token>" \
  -d '{"taskId": xxx, "message": "金额不正确，请修改"}'

# 发起人修改业务数据（businessId=1001），重新发起
curl -X POST http://localhost:8091/flowIns/start \
  -H "Authorization: Bearer <token>" \
  -d '{"flowCode":"expense-approval","businessId":"1001","variable":{"amount":500}}'
```

## 5. 与业务系统对接

### 5.1 业务表关联模式

在你的业务表中添加流程关联字段：

```sql
ALTER TABLE mk_leave_request ADD COLUMN flow_instance_id BIGINT COMMENT '流程实例ID';
ALTER TABLE mk_leave_request ADD COLUMN flow_status VARCHAR(32) COMMENT '流程状态';
```

### 5.2 业务代码集成示例

```java
@Service
@RequiredArgsConstructor
public class LeaveRequestService {

    private final IFlowInsService flowInsService;

    /**
     * 提交请假申请，同时发起审批流程
     */
    public void submitLeaveRequest(LeaveRequestDto dto) {
        // 1. 保存业务数据
        LeaveRequest request = saveLeaveRequest(dto);
        
        // 2. 发起审批流程
        StartFlowDto flowDto = new StartFlowDto();
        flowDto.setFlowCode("leave-apply");
        flowDto.setBusinessId(String.valueOf(request.getId()));
        flowDto.setMessage(dto.getReason());
        Map<String, Object> variables = new HashMap<>();
        variables.put("days", dto.getDays());
        variables.put("type", dto.getLeaveType());
        flowDto.setVariable(variables);
        
        FlowInsVo flowIns = flowInsService.start(flowDto);
        
        // 3. 记录流程实例ID
        request.setFlowInstanceId(Long.valueOf(flowIns.getId()));
        updateLeaveRequest(request);
    }
}
```

### 5.3 流程事件监听

在流程节点到达时执行业务逻辑：

```java
@Component
public class LeaveApprovalListener implements Listener {
    
    @Override
    public void notify(ListenerVariable variable) {
        Instance instance = variable.getInstance();
        Map<String, Object> vars = variable.getVariable();
        
        // 当流程到达"部门经理审批"节点时
        if ("2".equals(instance.getNodeCode())) {
            // 发送通知邮件
            sendApprovalEmail(instance);
        }
        
        // 当流程结束时
        if ("complete".equals(instance.getFlowStatus())) {
            // 更新业务数据状态
            updateBusinessStatus(instance.getBusinessId(), "approved");
        }
    }
}
```

                    ┌─────────┐
                    │  开始    │
                    └────┬────┘
                         │ 启动流程 (start)
                         ▼
                    ┌─────────┐
              ┌─────│  待办    │
              │     │ (toDo)  │
              │     └────┬────┘
              │          │
       pass  ─┤          ├── reject
              │          │
              ▼          ▼
        ┌─────────┐  ┌─────────┐
        │ 已通过   │  │ 已驳回   │
        │ (pass)  │  │(reject) │
        └────┬────┘  └─────────┘
             │
      ┌──────┴──────┐
      │ 还有下个节点? │
      └──────┬──────┘
       是    │     否
        ▼          ▼
   ┌─────────┐  ┌─────────┐

## 7. 角色与权限配置参考

### 7.1 建议的角色划分

| 角色 | roleCode | 流程权限 |
|------|----------|---------|
| 超级管理员 | `super_admin` | 全部流程权限 |
| 部门经理 | `dept_manager` | 流程任务审批 |
| 普通用户 | `user` | 发起流程、查看自己的任务 |

### 7.2 菜单权限树

```
流程管理
├── 流程定义管理 (system:flow:def:*)
│   ├── 列表  (system:flow:def:list)
│   ├── 新增  (system:flow:def:add)
│   ├── 编辑  (system:flow:def:edit)
│   └── 删除  (system:flow:def:delete)
├── 流程实例管理 (system:flow:ins:*)
│   ├── 列表  (system:flow:ins:list)
│   ├── 发起  (system:flow:ins:start)
│   ├── 编辑  (system:flow:ins:edit)
│   └── 删除  (system:flow:ins:delete)
└── 流程任务管理 (system:flow:task:*)
    ├── 我的待办 (system:flow:task:list)
    └── 任务审批 (system:flow:task:approve)
```

### 7.3 权限分配示例

```sql
-- 给超级管理员分配所有流程权限
INSERT INTO mk_sys_role_permissions (role_id, permission_id)
SELECT r.id, p.id
FROM mk_sys_role r, mk_sys_permissions p
WHERE r.role_code = 'super_admin'
  AND p.permission LIKE 'system:flow:%';

-- 给普通用户分配发起流程和查看待办的权限
INSERT INTO mk_sys_role_permissions (role_id, permission_id)
SELECT r.id, p.id
FROM mk_sys_role r, mk_sys_permissions p
WHERE r.role_code = 'user'
  AND p.permission IN ('system:flow:ins:start', 'system:flow:task:list');
```

## 8. 常见问题

### Q1: 启动后流程设计器页面 404？

检查 `warm-flow-plugin-ui-sb-web` 依赖是否引入，确认 `pom.xml` 中有：
```xml
<dependency>
    <groupId>org.dromara.warm</groupId>
    <artifactId>warm-flow-plugin-ui-sb-web</artifactId>
    <version>1.8.7</version>
</dependency>
```

### Q2: 流程表未自动创建？

确保 `application.yml` 中 MyBatis-Plus 没有禁用 DDL：
```yaml
mybatis-plus:
  global-config:
    db-config:
      # 不要设置 table-prefix，flow_ 表前缀由实体注解控制
```

若仍不创建，手动执行 DDL（从内网环境导出）。

### Q3: 待办列表为空？

检查：
1. 当前登录用户是否切换为处理人角色的账号
2. 流程节点的权限标识是否与当前用户角色匹配
3. 是否已发布并启动了流程

### Q4: 操作提示 "Token 无效或已过期"？

1. 确认请求头携带了 `Authorization: Bearer <token>`
2. 检查 Token 是否过期（登录接口返回 `expiresTime`）
3. 流程设计器需要在 URL 中传 `?token=xxx`

### Q5: 设计器保存失败？

设计器调用的是 `/warm-flow/saveJson`，确保 URL 中带了 `?token=xxx`。

### Q6: handler 还是存成了用户ID，怎么显示姓名？

改造后所有 API 返回的 VO 中都新增了 `createByName` 字段，直接展示即可。管理页面也填充了 `createByName`。前端无需额外查询。

### Q7: 如何区分待办、已办、全部实例？

| 接口 | 说明 |
|------|------|
| `GET /flowTask/myTodo` | 我的待办（当前用户需要处理的） |
| `GET /flowTask/myDone` | 我的已办（当前用户处理过的） |
| `GET /flowIns/list` | 全部流程实例（需要相应权限） |

## 9. 调试技巧

### 9.1 开启 SQL 日志

`application.yml` 中启用 MyBatis-Plus SQL 日志：
```yaml
mybatis-plus:
  configuration:
    log-impl: org.apache.ibatis.logging.stdout.StdOutImpl
```

启动后可看到所有流程引擎的 SQL 语句。

### 9.2 直接调用 WarmFlowTest

项目中内置了 `WarmFlowTest.java` 测试类，包含流程部署、启动、审批等全流程测试。可在单元测试中调用：

```java
@SpringBootTest
class FlowTest {
    @Autowired
    private WarmFlowTest warmFlowTest;
    
    @Test
    void testFullFlow() throws Exception {
        warmFlowTest.deployFlow();     // 部署流程
        warmFlowTest.publish();        // 发布
        warmFlowTest.startFlow();      // 启动
        warmFlowTest.skipFlow();       // 审批
    }
}
```

### 9.3 查看流程定义 JSON

```bash
curl http://localhost:8091/flowDef/design/<definitionId> \
  -H "Authorization: Bearer <token>"
```

返回完整的流程设计 JSON，可用于排错或导出备份。
